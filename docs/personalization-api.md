# Авторизация и личный календарь

Каталог, карточки олимпиад, календарь и публичная статистика доступны без входа.
Изменение личного плана и результатов требует сессии ЛК «Силаэдр» и
заголовка `X-CSRF-Token`.

## Настройка OIDC

Backend использует Authlib, discovery, Authorization Code, `state`, `nonce` и
PKCE `S256`. Для production задаются:

```dotenv
REDIS_URL=redis://redis:6379/2
APP_BASE_URL=https://olympiads.example.ru
FRONTEND_BASE_URL=https://olympiads.example.ru
CRM_OIDC_ISSUER=https://lk.silaeder.ru
CRM_OIDC_CLIENT_ID=olympiads
CRM_OIDC_CLIENT_SECRET=...
CRM_OIDC_SCOPES=openid profile email roles
SESSION_COOKIE_SECURE=true
```

В OIDC-клиенте CRM регистрируются точные адреса:

```text
https://olympiads.example.ru/auth/crm/callback
https://olympiads.example.ru/auth/crm/logout/callback
```

Локальная личность связывается только по уникальной паре `(issuer, sub)`. Email,
роль, имя и класс синхронизируются при входе. Класс приходит как claim `grade`
в составе scope `profile`; локальное поле является только кэшем последнего
значения CRM. Токены не передаются Vue; сессии хранятся в Redis.

## Auth и профиль

- `GET /api/v1/auth/session` — всегда `200`; возвращает `authenticated`, `user`,
  `csrf_token` и `login_url`.
- `GET /api/v1/auth/login?next=/relative/path` — перенаправляет в CRM. Внешние и
  protocol-relative значения `next` отклоняются.
- `GET /auth/crm/callback` — OIDC callback и переход на безопасный `next`.
- `POST /api/v1/auth/logout` — требует сессию и CSRF; возвращает `logout_url` для
  перехода на RP-Initiated Logout CRM.
- `GET /api/v1/me` — локальный профиль.
- `PATCH /api/v1/me` оставлен для совместимости, но возвращает `409`: класс
  изменяется в ЛК и обновляется здесь при следующем входе.

Ответ авторизованной сессии:

```json
{
  "authenticated": true,
  "user": {
    "id": 1,
    "name": "Иван Иванов",
    "email": "ivan@example.ru",
    "preferred_username": "ivan",
    "role": "student",
    "object_type": "students",
    "grade": 9
  },
  "csrf_token": "...",
  "login_url": "/api/v1/auth/login"
}
```

## Личный план

- `GET /api/v1/me/plan?academic_year=2026/27` — все записи плана и ближайшие
  датированные этапы. Собственные архивные планы также входят в `items` с
  `edition_status=archived`, но не входят в `upcoming_stages`.
- `GET /api/v1/olympiads/{slug}/planning?academic_year=2026/27` — публичный
  `participant_count`, добровольно опубликованные имена и `plan` текущего
  пользователя либо `null`.
- `POST /api/v1/olympiads/{slug}/planning` — добавить, ответ `201`.
- `PATCH /api/v1/olympiads/{slug}/planning` — изменить настройки.
- `DELETE /api/v1/olympiads/{slug}/planning` — удалить план и его прогресс.

Поля записи плана:

```json
{
  "status": "planned",
  "is_name_public": true,
  "reminders_enabled": true,
  "reminder_days_before": [7, 1]
}
```

`status`: `planned`, `registered`, `participating` или `completed`. Для новой
записи плана публикация имени включена по умолчанию; пользователь может сразу
выключить её в настройках. Пустой список дней допустим только при выключенных напоминаниях.
При `reminders_enabled=true` пользователь также получает через ЛК однократное
уведомление, когда после добавления в план регистрация переходит в состояние
`open`. Повторный импорт неизменного каталога уведомление не дублирует.
`edition_status` имеет значение `published` или `archived`. Новую архивную
карточку добавить нельзя, а её публичные detail/planning endpoints возвращают
`404`; уже существующий собственный архивный план разрешено изменить или удалить,
чтобы отозвать публикацию имени и очистить сохранённые результаты.

## Прогресс этапа

- `PUT /api/v1/olympiads/{slug}/stages/{stage_id}/progress` — создать или заменить
  отметку.
- `DELETE /api/v1/olympiads/{slug}/stages/{stage_id}/progress` — сбросить отметку.

```json
{
  "participated": true,
  "advanced": true,
  "result": "Диплом II степени"
}
```

Если `participated=false`, backend канонически сбрасывает `advanced` и `result` в
`null`. У этапов есть стабильный `key`: повторный импорт сопоставляет этапы по нему,
а исчезнувшие из источника этапы архивируются вместо удаления. Поэтому вставка или
перестановка этапов не переносит и не стирает пользовательские результаты.

Все state-changing endpoints сначала возвращают `401` анонимному клиенту. Для
авторизованного клиента отсутствующий или неверный CSRF-токен даёт `403`.

## Мой класс

Раздел `/my-class` доступен пользователям ЛК с ролью `teacher` или `admin`.
Каждый ведёт собственный список; одного ученика могут добавить несколько учителей.
Резервный локальный администратор также может вести отдельный список (ссылка из
админки), но уведомления требуют учётной записи ЛК и её OIDC `sub`.

- `GET /api/v1/my-class` — ученики владельца и их олимпиады за `academic_year`
  (по умолчанию текущий учебный год), `notifications_available` и CSRF-токен.
- `GET /api/v1/my-class/candidates?q=Анна&grade=9` — поиск среди учеников,
  вошедших в календарь; до 100 результатов, без уже добавленных.
- `POST /api/v1/my-class/students` с `{"student_id": 123}` — добавить ученика;
  повторное добавление идемпотентно.
- `DELETE /api/v1/my-class/students/123` — убрать только из собственного класса;
  личный план ученика сохраняется.

Операции записи требуют `X-CSRF-Token`. Справочник и списки класса закрыты от
гостей и учеников, ответы имеют `Cache-Control: private, no-store`.

Учителя и администраторы ЛК получают групповые уведомления об активных планах
своих учеников (`planned`, `registered`, `participating`), независимо от настроек
личных напоминаний учеников и публикации имени. За 7 дней и за день до
подтверждённого активного этапа, а также в день открытия регистрации, создаётся
одно сообщение на владельца, сезон олимпиады и календарный день в Москве.
Оно объединяет события и содержит список учеников, добавивших олимпиаду в план.
Открытие регистрации учитывается для подписок и планов, существовавших на момент
открытия. Завершённые планы и архивные олимпиады не создают уведомлений.

Outbox `class_notification_dispatches` обрабатывается существующим `reminders.scan`.
Уникальное ограничение и стабильный `Idempotency-Key` защищают от дублей.
Перед первой отправкой состав проверяется заново; после первой попытки тело
фиксируется для повторов. Если состав или событие изменились между попытками,
отправка отменяется. Удаление ученика прекращает будущие уведомления по нему.

### Справочник school-crm

В проверенной локальной версии school-crm есть `GET /api/users` (только для
администратора CRM) и `GET /api/objects/students` (с пользовательской авторизацией
и проверкой доступа к объектам). Внешнего endpoint со списком учеников для
OIDC-клиента нет; `/oidc/userinfo` возвращает только вошедшего пользователя.
Поэтому в текущей версии добавляются только ученики, уже вошедшие в календарь.
school-crm не изменён. Для добавления до первого входа потребуется отдельный
защищённый справочник, возвращающий стабильный OIDC `sub` объекта ученика.
