# Календарь олимпиад

Сервис для школьников 5–11 классов: поиск олимпиад по классу, профилю и
статусу перечня, карточное и календарное представления, этапы с уровнем
достоверности дат, материалы прошлых лет, льготы/призы и первичные источники.
Каждый профиль хранится как отдельная олимпиада.

Просмотр каталога, календаря, материалов, числа участников и добровольно
опубликованных имён доступен без входа. После входа через ЛК «Силаэдр» ученик
может указать класс, добавить олимпиаду в личный план, настроить напоминания и
отмечать участие, проход на следующий этап и результат.

Срез каталога сделан 26 августа 2026 года для 2026/27 учебного года. В текущем
seed — 357 карточек; у всех есть проверенные материалы, а все 102 популярные
карточки покрыты. У 356 карточек есть именно задания, решения или архивы
прошлых лет; только для нового биологического профиля ведомственной олимпиады
пока опубликован официальный syllabus. Всего сохранено 473 связи с 286
уникальными URL. Числовые классы подтверждены для 352
карточек; у остальных пяти музыкальных направлений сохранены точные категории
участников из регламентов. Структура этапов есть у всех 357 карточек: всего 914
этапов, из них 633 с датой, диапазоном или подтверждённым дедлайном и 172 с
подтверждёнными датами или дедлайнами. Два соревнования с календарным циклом,
не совпадающим с обычным учебным сезоном, имеют отдельную явную метку. В
каталоге 359 записей о льготах/призах; для 155 карточек указан
официальный вузовский ориентир по правилам приёма-2026. В частности, отдельно
проверены все 28 старших профилей олимпиад I уровня, у которых раньше не было
конкретной вузовской связи. Статус регистрации
проверен у всех 357 карточек; на момент среза только 50 действительно открытых
заявок получают кнопку регистрации, а анонсы, закрытые и прошлогодние формы её
не получают. Для краткоживущих форм CTA автоматически исчезает после
подтверждённого дедлайна, даже до следующей пересборки каталога. В карточке
показываются результат и дата последней ручной проверки регистрации.

> Перечень Минобрнауки на 2026/27 пока не утверждён. Профили из проекта помечены
> «Проект перечня», а не «утверждено». Последний действующий приказ относится к
> 2025/26. Полное обоснование: [официальный отчёт](research/official_status_report.md).

## Возможности и стек

- Flask, Flask-SQLAlchemy, Flask-Migrate и PostgreSQL;
- Vue 3, Vite, Bootstrap 5 и Font Awesome — зависимости из npm, без CDN;
- OpenID Connect через Authlib: Authorization Code, discovery, `state`, `nonce`
  и PKCE `S256`;
- server-side пользовательские сессии в Redis, `HttpOnly`/`SameSite=Lax` cookie
  и CSRF для операций записи;
- Celery worker и Celery beat для durable-напоминаний через API ЛК;
- единый Docker Compose для сервера и локальной проверки production-сборки.

Публичное API не требует входа. Пользовательские операции без сессии возвращают
`401`, а с отсутствующим или неверным `X-CSRF-Token` — `403`. Админка использует
отдельную локальную учётную запись и не зависит от роли пользователя в CRM.

## Запуск через Compose

Требуются Docker и Docker Compose.

```bash
cp .env.example .env
# Заполните SECRET_KEY, POSTGRES_PASSWORD, домен и реквизиты ЛК в .env.
docker compose up --build -d
docker compose exec api flask --app wsgi import-catalog --sync /data/seed/catalog.json
docker compose exec api flask --app wsgi create-admin
```

`compose.yaml` — единственный Compose-файл проекта. Он запускает production-сборку
frontend через nginx, Flask через Gunicorn, PostgreSQL, Redis, миграции, Celery
worker и ровно один Celery beat. PostgreSQL и Redis наружу не публикуются; API и
frontend доступны внешнему nginx только на `127.0.0.1`.

Для локальной проверки без HTTPS замените в `.env` три URL на localhost,
укажите `CORS_ORIGINS=http://localhost:5188` и
`SESSION_COOKIE_SECURE=false`.

Команда `create-admin` требует пароль длиной не менее 12 символов; то же правило
действует при смене пароля существующего редактора.

После запуска:

- каталог: <http://localhost:5188>;
- личный план: <http://localhost:5188/my-plan>;
- админка: <http://localhost:5188/admin>;
- readiness API (PostgreSQL + Redis): <http://localhost:5050/api/health>;
- liveness процесса: <http://localhost:5050/api/live>.

Календарь открывается переключателем над результатами. Выбранный режим, месяц и
фильтры сохраняются в URL. Точные названия 134 профилей организаторов объединены
в 32 понятных направления поиска. Сами карточки не объединяются: профиль,
уровень, этапы, материалы и льготы остаются самостоятельными. Междисциплинарный
профиль может находиться сразу в нескольких направлениях, а старые ссылки с
точным параметром `profile` продолжают работать.

Публичный каталог и календарь сохраняют олимпиады текущего сезона при любом
состоянии публикации формы: открыта, анонсирована, ещё не открыта или пока не
найдена. Из выдачи исключается только карточка с точным прошедшим временем
закрытия регистрации; сама кнопка регистрации показывается исключительно для
действующей формы. В интерфейсе оставлены поиск, направление, класс, уровень и
вуз.
Выбор вуза означает наличие подтверждённой льготы или условия поступления именно
в этом вузе; призы не считаются совпадением. В карточке показывается конкретное
право и год приёма; общая законная БВИ ВсОШ не требует фиктивной привязки к вузу.
Bulk-endpoint этапов доступен по
`GET /api/v1/calendar?academic_year=2026%2F27&month=2026-09`.
Если организатор ещё не опубликовал новый календарь, прошлогодние день и месяц
могут показываться как неподтверждённый прогноз на 2026/27 с отдельной пометкой;
такие даты не смешиваются с официально подтверждёнными.

Без `CRM_OIDC_CLIENT_ID` и `CRM_OIDC_CLIENT_SECRET` публичная часть и админка
работают полностью, а вход через ЛК возвращает `503` с понятным сообщением.

### Включение ЛК в локальной среде

В CRM нужно создать конфиденциальный OIDC-клиент, разрешить роли пользователей и
scopes `openid profile email roles`, а для напоминаний включить право отправлять
внешние уведомления. Зарегистрированные адреса должны совпадать посимвольно:

```text
Redirect URI:             http://localhost:5050/auth/crm/callback
Post-logout redirect URI: http://localhost:5050/auth/crm/logout/callback
```

HTTP разрешён CRM только для `localhost` и `127.0.0.1`. Поэтому локальный вход
проверяется через <http://localhost:5188>, а не через LAN-адрес вида
`http://192.168.x.x:5188`.

Затем заполните `.env`:

```dotenv
SECRET_KEY=<длинный случайный секрет>
APP_BASE_URL=http://localhost:5050
FRONTEND_BASE_URL=http://localhost:5188
SESSION_COOKIE_SECURE=false

CRM_OIDC_ISSUER=https://lk.silaeder.ru
CRM_OIDC_CLIENT_ID=olympiads-local
CRM_OIDC_CLIENT_SECRET=<секрет из CRM>
CRM_OIDC_SCOPES=openid profile email roles
CRM_NOTIFICATION_URL=https://lk.silaeder.ru/api/external/notifications
CRM_NOTIFICATION_MAX_ATTEMPTS=12
CRM_NOTIFICATION_MAX_AGE_DAYS=1
```

Те же `client_id`/`client_secret` используются backend для HTTP Basic при
отправке уведомлений. Секрет и OIDC-токены никогда не попадают во Vue.

После изменения переменных пересоздайте процессы:

```bash
docker compose up --build -d --force-recreate api worker beat
```

## Production-настройка

Рекомендуется один HTTPS-origin, например `https://olympiads.example.ru`:
reverse proxy направляет `/api/*` и `/auth/crm/*` в Flask, а остальные маршруты —
в собранное Vue-приложение. Минимальные значения:

```dotenv
SECRET_KEY=<стойкий случайный секрет не короче 32 символов, общий для всех API-инстансов>
ALLOW_INSECURE_DEV_SECRET=false
DATABASE_URL=postgresql+psycopg://<user>:<password>@<postgres-host>:5432/<database>
APP_BASE_URL=https://olympiads.example.ru
FRONTEND_BASE_URL=https://olympiads.example.ru
CORS_ORIGINS=https://olympiads.example.ru
SESSION_COOKIE_SECURE=true
REDIS_URL=redis://<redis-host>:6379/2
CELERY_BROKER_URL=redis://<redis-host>:6379/0
CELERY_RESULT_BACKEND=redis://<redis-host>:6379/1

CRM_OIDC_ISSUER=https://lk.silaeder.ru
CRM_OIDC_CLIENT_ID=olympiads
CRM_OIDC_CLIENT_SECRET=<production secret>
CRM_OIDC_SCOPES=openid profile email roles
CRM_NOTIFICATION_URL=https://lk.silaeder.ru/api/external/notifications
CRM_NOTIFICATION_MAX_ATTEMPTS=12
CRM_NOTIFICATION_MAX_AGE_DAYS=1
```

Эти значения задаются в единственном `.env`, который читает `compose.yaml`.
Отдельного production override нет. Redis-базы уже разведены внутри Compose:
`/0` — Celery broker, `/1` — результаты Celery, `/2` — пользовательские сессии.
Пошаговый запуск и конфигурация внешнего nginx описаны в
[инструкции по развёртыванию](docs/production-deployment.md).

В CRM регистрируются ровно:

```text
https://olympiads.example.ru/auth/crm/callback
https://olympiads.example.ru/auth/crm/logout/callback
```

Необходимо запустить `api`, минимум один `worker` и ровно один планировщик
`beat`. Beat ежедневно в 07:00 `Europe/Moscow` создаёт записи outbox для
подтверждённых активных этапов. Worker отправляет их в ЛК со стабильным
`Idempotency-Key`; таймауты, `429` и `5xx` повторяются с backoff и jitter, а
остальные `4xx` фиксируются как постоянная ошибка. По умолчанию transient retry
ограничен 12 попытками и одним днём после запланированной даты. ЛК самостоятельно
доставляет принятое уведомление в настроенные пользователем каналы.

PostgreSQL и Redis не следует публиковать наружу. Доверие к forwarded-заголовкам
должно быть ограничено reverse proxy; внешние callback URL строятся из
фиксированного `APP_BASE_URL`. Реальные секреты не коммитятся. Для
`POST /api/admin/session` на reverse proxy следует включить rate limit попыток
входа; приложение само не использует in-memory limiter, который расходился бы
между несколькими Gunicorn worker.

Перед rollout API/worker/beat запустите отдельный одноразовый job тем же backend
image с командой `flask --app wsgi db upgrade` и дождитесь успешного завершения.
Не запускайте миграции одновременно на каждом API replica. Локальный Compose
уже содержит такой сервис `migrate`, а readiness API проверяет и PostgreSQL, и
Redis до допуска трафика.

## Импорт и сохранность пользовательских данных

В Compose миграции применяет одноразовый сервис `migrate` до запуска
остальных backend-процессов. Импорт без `--sync` идемпотентно добавляет и
обновляет переданные сезоны. С `--sync` файл считается
полным снимком затронутых учебных годов: отсутствующие в нём сезоны переводятся в
`archived`, но не удаляются.

У каждого этапа есть стабильный `Stage.key`. Сборщик seed формирует его
детерминированно, импорт сопоставляет этапы по ключу, а исчезнувшие этапы помечает
`is_active=false`. Поэтому вставка, перестановка или снятие этапа не переносит и
не уничтожает сохранённые результаты учеников. Hard-delete олимпиады запрещён,
пока она присутствует хотя бы в одном личном плане. Если `--sync` архивировал
карточку, собственный план и результаты остаются видны на странице «Мой план»,
но не попадают в ближайшие события. Владелец может отключить публикацию имени и
напоминания либо удалить архивный план; публичные endpoints архивную карточку не
возвращают.

## Разработка и проверки

Backend локально:

```bash
python3 -m venv .venv
.venv/bin/pip install -e 'backend[dev]'
cd backend
../.venv/bin/pytest
../.venv/bin/ruff check . ../scripts/build_catalog.py
```

Frontend:

```bash
cd frontend
npm install
npm run test:run
npm run build
```

Пересобрать импортный файл из проверенных research-срезов:

```bash
python3 scripts/build_catalog.py
python3 scripts/validate_material_urls.py
```

Сборщик не обращается в интернет и не является автопарсером: он детерминированно
объединяет сохранённые исследования. Валидатор реальными GET-запросами проверяет
все уникальные ссылки и обновляет [отчёт аудита](research/material_link_audit.md).
Текущее покрытие и честный список карточек без публичного архива приведены в
[отчёте о материалах](research/materials_coverage_report.md). Правила
достоверности описаны в [политике данных](docs/data-policy.md), а покрытие
классов и этапов — в [отчёте структуры](research/catalog_structure_sources.md).
Полный срез статусов и оговорки по краткоживущим формам находятся в
[отчёте о регистрации](research/registration_coverage_report.md).
OIDC и personal API описаны в
[документации персонализации](docs/personalization-api.md), общая схема — в
[архитектуре](docs/architecture.md). Основной импортный файл —
[data/seed/catalog.json](data/seed/catalog.json).

## Структура

```text
backend/        Flask API, OIDC, модели, миграции, Celery и тесты
frontend/       Vue-приложение и тесты компонентов
data/seed/      готовый импортируемый каталог
research/       первичные срезы, источники, аудиты и сравнение перечней
scripts/        детерминированная сборка и проверка seed
docs/           архитектура, API и политика данных
```

Остановить сервис без удаления данных:

```bash
docker compose down
```

PostgreSQL сохраняется в именованном volume. `docker compose down -v` удаляет
его без возможности восстановления и для обычного перезапуска не нужна.

Конкретные правила вузов на приём-2027 намеренно не додумывались: они
публикуются ежегодно. Схема хранит вуз, вид льготы, диплом, предмет/порог ЕГЭ,
год и официальную ссылку; следующий содержательный срез нужен после публикации
правил приёма-2027.
